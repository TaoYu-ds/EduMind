# EduMind 简历包装指南

本文档用于把 EduMind 项目包装成简历、面试和项目展示中可讲清楚的经历。建议按真实实现描述，量化数据如果没有压测或标注集支撑，应写成“设计目标”或“在内置评测集上”。

包装重点：EduMind 当前不建议只包装成“智能客服 Agent”，更适合定位为“在线教育多 Agent 学习辅导系统 / Multi-Agent Tutoring Orchestrator”。项目已经支持细粒度意图识别（知识点/作业/计划/考试/课程推荐）、结构化路由决策、主辅 Agent 协同（Tutor + Plan）、学科章节结构化 RAG、教学合规与拒绝代写、学习画像、动态 Skills、Monitor 路由降权和 LLM-as-Judge 评测闭环。这是区分“普通聊天 Demo”和“可观测、可评测、可持续迭代 Agent 工程项目”的关键点。

## 项目一句话描述

> EduMind 是一个面向在线教育辅导的多 Agent 编排运行时，集成细粒度教学意图识别、结构化主辅 Agent 路由（讲题 / 计划 / 考试）、学科章节结构化 RAG、学习画像、动态 Skills 教学规范、MCP 工具可靠性治理、Monitor 在线降权闭环和 LLM-as-Judge 端到端评测。

### Java / Spring Boot 版本

适合投 Java 后端、AI 应用工程、平台工程方向时使用。重点突出：不是简单把 Python 改写成 Java，而是用 Spring 生态重构了一套可部署、可观测、可评测的 Agent 服务。注意：Java 版目前仍是电商客服场景，与 Python 版的教育场景不同，面试时不要把两边的业务示例混着讲。

```text
EduMind Java 多 Agent 客服编排平台
技术栈：Java 21 / Spring Boot 3.5 / Spring AI / LangChain4j / Redis / Maven / Micrometer / Prometheus / Docker Compose / Swagger

- 基于 Spring Boot 3.5 重构 EduMind 后端服务，提供 `/chat`、`/search`、`/skills`、`/monitor`、
  `/metrics`、`/eval/run` 等接口，并通过 Springdoc OpenAPI 提供 Swagger 文档，支持 Docker Compose 一键部署。
- 使用 Spring AI 封装 Anthropic 与 DeepSeek 模型调用，支持通过 Spring Profile 在 `anthropic` 和 `deepseek`
  之间切换，并实现 LLM 调用失败时的本地 fallback，降低开发和演示环境对外部模型服务的强依赖。
- 设计 Java 版细粒度意图识别模块，结合 LLM Few-shot、字符 n-gram 语义相似度和关键词 Pattern 三路融合，
  输出 `intent`、`intent_group`、`intent_confidence`、`source_scores`、紧急度和结构化实体；
  支持退款、发票、重复扣款、登录 401、页面 500、物流、转人工等业务细分类。
- 实现结构化多 Agent 编排器 `AgentOrchestrator`，基于意图、关键词和实体计算 `general/technical/billing`
  领域分数，生成 `primary_agent`、`supporting_agents`、`routing_reason` 和 `routing_confidence`，
  并对“登录异常 + 重复扣款”等复合问题进行主辅 Agent 并行处理和结果合并。
- 构建 Java 版 Hybrid RAG 知识库链路，文档导入后使用 LangChain4j 进行切片，
  结合 BM25 关键词得分、本地 hash vector 语义得分和 LLM rerank 完成召回排序，
  并通过按意图触发的 RAG gating 避免问候、转人工、未知意图等请求产生无效检索。
- 实现 `KnowledgeToolManager` 工具治理能力，为知识库检索增加查询改写、多子查询并行召回、TTL 缓存、
  超时控制、熔断器、fallback 降级、rerank 和工具统计，提升 RAG 工具链可靠性。
- 设计 Redis + JSON 持久化记忆体系：Redis 保存当前会话工作记忆，
  JSON store 保存历史会话摘要、长期记忆和用户画像，在 Java 版中实现与 Python 版用户可见效果一致的记忆恢复能力。
- 实现动态 Skills 加载机制，支持从 `skills/*/SKILL.md` 读取通用客服、技术支持、账单退款规则，
  按 Agent 类型和用户消息关键词注入 system prompt，并通过 `/skills/reload` 实现运行时热加载。
- 搭建 Monitor 在线观测闭环，基于 Micrometer/Prometheus 暴露 Agent 成功率、延迟和工具统计，

- 实现 Java 版端到端评测能力，覆盖 Intent Accuracy、Macro-F1、per-class Precision/Recall/F1、
```

### 端到端 Agent 怎么评测？

**回答思路**

评测分两部分：

1. 意图识别评测：用标注用例计算 Accuracy 和 Macro-F1。
2. 端到端回复评测：真实调用 `Orchestrator.run()` 生成回复，再用 LLM-as-Judge 从四个维度打分。

四个维度是：

- `relevance`：是否回答用户问题。
- `accuracy`：信息是否准确。
- `completeness`：是否完整解决需求。
- `helpfulness`：用户能否据此行动。

评测器还会和上一轮结果对比，如果某个指标退化超过 5%，会标记为 regression，并生成优化建议。
